# Дневник Никиты

## Материалы

- [Дневник Никиты в YouGile](https://ru.yougile.com/team/5d37d1949ade/kb-cdff8f4aec10).
- Приложенная статья «Автоматизация тестирования программного обеспечения: ключевые методологии и подходы», с. 107–116.
- Приложенный ГОСТ Р ИСО/МЭК 25010–2015, модель качества программного продукта.
- Видео Кирилла Македонского — [pytest на FastAPI](https://www.youtube.com/watch?v=qVvZ7_FjHgo) и [CI/CD на реальных проектах](https://www.youtube.com/watch?v=axl0UfqDPZs).

## Что применили

| Тема | Изменение в Dreamteam | Как проверить |
|---|---|---|
| Воспроизводимая автоматизация из статьи | [Моделирование Mirage](../../backend/dreamteam/domain/simulation.py) получает источник случайных чисел извне. В тесте можно задать значения для каждого раунда и повторить тот же исход. | [Модульные тесты](../../backend/tests/test_simulation.py) проверяют 50/50 и 55/45, смену сторон и решающий раунд при 12:12. |
| Функциональная пригодность по модели качества ГОСТ | Ведущий начинает за T, сервер берёт тактики для текущих сторон, счёт заканчивается на 13 победах. На нажатие «Я готов» двух игроков отвечает одна транзакция запуска. | [Проверки API и БД](../../backend/tests/test_game.py) сверяют результат у обоих игроков и число записей серии. |
| Надёжность и восстанавливаемость по модели качества ГОСТ | [Результат карты и раунды](../../backend/dreamteam/repositories/series.py) сохраняются в PostgreSQL. Повторное подтверждение готовности возвращает тот же результат. | Обновить приложение и сравнить результаты у обоих игроков. Проверка конкретных сценариев не является сертификацией по стандарту. |
| pytest и CI/CD | Тесты разделены на расчёт правил и проверки FastAPI с PostgreSQL. [Существующий workflow](../../.github/workflows/verification.yml) запускает backend-тесты, сборку React и браузерную проверку. | Прогнать обе группы по [инструкции](../../README.md). |
